02 — Hierarchy & lifecycle

03 — Attendance that can’t be faked

A signed QR that dies in 30 seconds, plus a 500 m geofence

The event screen shows a JWT that expires every 30 seconds, so a screenshot sent to a friend is useless. When a student scans, the server also checks their GPS position against the venue with the haversine formula.

// POST /qr/attendance (simplified from the real controller)
const { token, lat, lng } = req.body;
const { eventId } = jwt.verify(token, process.env.QR_SECRET); // signed with expiresIn: "30s"
const event = await Event.findById(eventId);
const [vLng, vLat] = event.location.coordinates;
const distance = getDistanceInMeters(lat, lng, vLat, vLng); // haversine
if (distance > 500) return res.status(403).json({ message: "You are not at the event location" });
Why both checks
Token and place

The 30-second token proves you’re looking at the screen now; the geofence proves you’re in the room. Either one alone is easy to beat.

04 — Judging

Judges score, leaderboards move, results lock

Judges get their own panel and login. Scores feed live event leaderboards and a global ranking, and once submitted they’re locked, so nobody can quietly change a result afterwards.

05 — Rewards

Points that add up to a tier

Students earn reward points per event. Clubs and colleges accumulate points and climb tiers, which gives campuses a reason to keep their events on the platform.

06 — API platform

The whole event engine, sold as an API

Outside organisers can run events through HackByteCodex with an API key: events, forms, registrations, judges and analytics. Plans are tier-gated, keys rotate, and every key gets its own rate limit.

Plans
Basic · Pro · Enterprise

5 / 25 / unlimited events a month, 100 / 1,000 / unlimited registrations per event, 3 / 15 / unlimited judges. Enforced by a tier guard on every route.

Billing
Razorpay subscriptions

Monthly or yearly orders, payment verification, and a raw-body webhook so subscription state can’t drift from what Razorpay says.

Keys
Rotate, expire, audit

Keys expire after 30, 90 or 365 days depending on plan, can be rotated (with an email to the owner), and API calls are written to an audit log.
